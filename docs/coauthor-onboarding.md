# Coauthor onboarding

A staged route from a local folder to a working GitHub-code/Dropbox-data research setup, for
Claude Code or Codex. Start with the small collaboration profile; add writing skills later when
needed. Each collaborator uses their own accounts and permissions.

**[Open the copy-and-paste prompt sequence](../skills/coauthor-github-workflow/references/onboarding-protocol.md).**

The full protocol lives inside `coauthor-github-workflow`, so the selective installer includes it
and installed agents can read it without access to this repository's root documentation.

## How to use it

1. The project owner fills in the protocol's setup card: repository, authority, approved data,
   first task, expected checks and any known gaps. Keep that completed card in the private project.
2. The collaborator pastes one stage at a time into their agent, starting with inspection.
3. Review each stage's result before continuing. Missing access is a question to resolve, not
   permission to substitute data, change methods or borrow another person's credentials.
4. Finish with a small, agreed reproduction pilot and a precise readiness report. A full rebuild
   or publication is a separate request.

## Where project-specific versions belong

Use the project's existing collaboration documentation, for example
`docs/collaboration/coauthors/ONBOARDING_PROMPTS.md`. Link it from the coauthor guide. It can contain
the actual private repository, approved snapshot IDs, task commands and dated readiness limits.
This public toolkit contains only reusable instructions and placeholders.
